03 / Wallet backends

The node that validates can serve your wallets.

Electrum runs inside rbitcoin, alongside the archive and mempool. Esplora REST and a documented subset of Bitcoin Core JSON-RPC are optional. You do not need a separate Electrum indexing process.

Choose the interface your client needs

Electrum
Confirmed and unconfirmed history, transaction broadcast, fee information, silent payment tweaks, and Electrum 1.6 package broadcast.
Esplora
A REST interface for wallet clients. It is an API, not a bundled graphical block explorer.
JSON-RPC
Chain, mempool, raw-transaction and decode methods, fee estimates, and a block-template selector. A subset, not the complete Bitcoin Core interface.

rbitcoin is a backend for wallet software. It does not provide a desktop wallet, hold your seed, or include a stratum pool server. Check the compatibility contract before pointing an existing integration at it.

Turn on Electrum deliberately

Electrum and Esplora require --sh-index; it is off by default. The transaction index used by the node is separate and always part of sync. Wallet serving must wait for the scripthash index to be ready.

After following the signet setup, stop the previous process cleanly before restarting the same test data directory with:

./rbitcoin-node --datadir ./datadir-signet \
  --network signet --milestone 0 \
  --sh-index --electrum-listen 127.0.0.1:50001

This listener is local to the machine. Use a signet-capable client with the same network selected. For mainnet sizing, budget the temporary index-building space as well as the settled archive.

Silent payments belong here

Silent payment tweaks are served through the Electrum surface. The project also supports Frigate scan-key subscriptions. These are specific backend capabilities, not a claim that every Electrum wallet supports silent payments.

Use a client that implements the corresponding protocol. The operator guide and compatibility notes define the supported behavior.

A familiar RPC shape, with boundaries

TCP JSON-RPC authenticates with a Bearer token from {datadir}/rpc.token. A Unix socket uses filesystem access control. Do not assume Bitcoin Core’s cookie or --rpcuser authentication works here.

There is no wallet RPC surface or coins-database UTXO scan. A matching method name is not a guarantee that every existing Core integration will work unchanged. Read the method and authentication reference.

Local first. Protect public listeners.

The node does not terminate TLS for these application interfaces. Keep them on loopback unless you deliberately configure remote access. Remote deployment needs appropriate TLS termination, authentication and network controls; a TLS proxy alone is not an access policy.

Application-level limits do not make a public, multi-tenant service turnkey. See security and operating expectations before exposing a backend.
