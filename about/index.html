A different answer to the coins database.

For years, Rearden wanted to get rid of dbcache. Not by making the cache bigger or tuning its flushes, but by changing the storage model that needed it.

Why another node?

rbitcoin explores a design between libbitcoin’s relational archive and Bitcoin Core’s block-file model: indexed history, no separate UTXO database, and wallet serving in the same process. Previous outputs come from the archive when the node needs them.

Its consensus implementation is independent, using Rust with rust-bitcoin types and libsecp256k1 cryptography. Sharing a consensus engine has value. So does testing different implementations against the same chain. rbitcoin takes the latter path without making independence a substitute for correctness.

How it was built

Brandon Black, known as Rearden or @reardencode, specified and directed the project. The official account describes Grok writing the code, with some help from Claude, using grok build and Cursor.

AI made it possible to implement a design that had been waiting for time and energy. That history belongs in the open. It neither replaces independent review nor changes the seriousness of consensus, network, or wallet-integrity bugs.

For the project’s own account, see Why rbitcoin exists and Rearden’s conversation with Pleb Underground.

Work on something concrete

Review a consensus edge case. Reproduce a bug. Improve a test or an explanation. Start with contributor setup, then use the issue tracker for non-sensitive work.

Vulnerabilities take a different route: report them privately. Do not put an unfixed exploit in a public pull request.
