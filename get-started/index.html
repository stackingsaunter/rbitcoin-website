01 / Get started

Start with signet. Then give it a disk.

rbitcoin validates the chain, keeps the full archive, and can serve wallets. Linux is the operator path. You can download a release or build a reproducible static binary with Nix.

Before the download

Plan for a 1 TB-class disk and a full archive: there is no pruning mode. Wallet indexes need additional working space while they are built. With two drives, inputs and witness can go on the slower one.

The project reports a roughly 720 GiB indexed mainnet archive, about 226 GiB of it hot, plus approximately 150 GiB of temporary hot-disk space while the wallet index packs. Those are measurements, not fixed requirements; leave room for growth. Read the storage breakdown.

Already running rbitcoin? Check the release notes and the schema-upgrade instructions first. The 0.7 line refuses populated 0.6.x stores and requires rebuilding the archive. Do not treat an upgrade as a binary swap or delete data without checking the exact migration.

Get the operator binary

Download from GitHub Releases. Each release supplies rbitcoin-node, rbitcoin-cli, and checksums. Choose Linux x86_64 musl for a fully static operator binary; compare it with the accompanying checksum before running it.

Windows x86_64 and Apple Silicon macOS builds are also published, but are less-proven snapshots. macOS builds are not notarized. This guide follows Linux.

Place both Linux binaries in a working directory and make them executable:

chmod +x rbitcoin-node rbitcoin-cli
./rbitcoin-node --help

Commands below assume that directory. Check the options against the release you downloaded.

Make a first connection

Signet is a test network. This short run checks that the node starts and reaches peers; it is not a complete sync or a mainnet-readiness test.

./rbitcoin-node --datadir ./datadir-signet \
  --network signet --listen 127.0.0.1:38333 \
  --milestone 0 --max-run-secs 120

Remove --max-run-secs 120 to keep syncing. The explicit --milestone 0 asks for historical script checks rather than relying on a network default. Leave the wallet interfaces off until you need them.

Mainnet is a separate decision

Mainnet operation is supported, but this is an independent consensus implementation in the pre-1.0 period. Compare its view of the chain with another implementation, monitor reorgs and disk headroom, and read the mainnet runbook before relying on it.

The documented default, --milestone 840000, skips script and signature checks at or below height 840,000. Other checks still run. Use --milestone 0 for every historical script. What that setting does—and does not—mean.

Prefer a reproducible build?

With Nix installed, build the static Linux binaries from a chosen revision. Matching source and lockfiles are necessary when reproducing a release.

git clone https://github.com/reardencode/rbitcoin.git
cd rbitcoin
# Select the release tag you intend to reproduce.
nix build .#rbitcoin-musl
./result/bin/rbitcoin-node --help

Run from result/bin/, or copy the binaries to your working directory. A regular release build inside a Nix development shell can depend on Nix’s glibc; it is not the portable musl build. See reproducible builds or contributor setup.
